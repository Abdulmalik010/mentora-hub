# DECISIONS.md — one line per architectural decision.

- 2026-10-28: Meta calls go through the OpenAI Python SDK pointed at the Meta base URL (Meta publishes no dedicated client; this is the docs' recommended path).
- 2026-10-28: Chat Completions protocol first for lower scaffold complexity; switch to Responses API later if multi-turn reasoning continuity proves necessary.
- 2026-10-28: Model IDs come only from env vars (META_MODEL_AGENT/FAST/TRANSCRIBE) with no code defaults, so credit spend stays configurable.
- 2026-10-28: META_BASE_URL defaults to the documented https://api.meta.ai/v1 but is env-overridable; META_API_KEY has no default and fails fast.
- 2026-10-28: Tool loop depends on a ChatClient protocol (SDK adapter in prod, fakes in tests) so agent logic is unit-testable with no network.
- 2026-10-28: Retries use our own exponential backoff (rate limits, transport/timeout errors, 5xx) with the SDK's built-in retries disabled to avoid stacked retry storms.
- 2026-10-28: Tables are created with db.create_all and no migrations until the schema stabilizes after the auth step.
- 2026-10-28: Roles/statuses/levels are plain strings without DB CHECK constraints; validation moves into forms/services when those steps land.
- 2026-10-28: User carries email (unique), password_hash (nullable until auth), display_name, role, is_sample flag and timestamps.
- 2026-10-28: Foreign keys are wired now (profiles→user, documents/casefiles/bookings→users, sessions→bookings, notes→student/session).
- 2026-10-28: Datetimes are stored naive UTC (SQLite has no tz-aware type); revisit with timezone-aware columns if we leave SQLite.
- 2026-10-28: ProfessorProfile.rate is a unit-less float; currency is decided at the booking step, not guessed now.
- 2026-10-28: Seed data is synthetic, @example.com emails, is_sample=True, "[SAMPLE DATA]" bios; seed is idempotent get-or-create by email.
- 2026-10-28: Email (Resend vs SMTP) and PDF (reportlab vs WeasyPrint) providers stay undecided; services are typed NotImplementedError stubs.
- 2026-10-28: Verified on the machine's Python 3.14 while keeping the code 3.11-compatible; no 3.11 interpreter is installed here.
- 2026-10-28: Pinned exact versions (Flask 3.1.3, Flask-SQLAlchemy 3.1.1, SQLAlchemy 2.1.6, Werkzeug 3.1.9, openai 3.40.0, python-dotenv 1.2.4, pytest 9.2.0) for reproducible builds.
- 2026-10-28: API key reads META_API_KEY first, MODEL_API_KEY second (docs-verified name); fail fast when neither is set.
- 2026-10-28: Session auth with Werkzeug hashes and no CSRF yet; Flask-WTF is mandatory before any shared deploy.
- 2026-10-28: Passwords need 8+ chars at the app layer; NULL-hash rows (seed) can never log in.
- 2026-10-28: Logout is POST-only; login honors relative next targets only (open-redirect guard); failures are generic to block enumeration.
- 2026-10-28: Home page is a factory-level route so the blueprint structure stays exactly as specified.
- 2026-10-28: Seed accounts share one env-provided demo password; seed refuses to run without SEED_DEMO_PASSWORD and reports sample rows only.
- 2026-10-28: SECRET_KEY has no default and the factory fails fast without it outside TESTING; cookies are HttpOnly + SameSite=Lax with Secure via SESSION_COOKIE_SECURE.
- 2026-10-28: Flask-WTF CSRFProtect guards every POST form including logout; pinned Flask-WTF 1.3.0.
- 2026-10-28: httpx 0.28.1 pinned for the Meta transcribe multipart call.
- 2026-10-28: Docs say native PDF input is a chat file block (base64 data URL + filename); DOCX is absent from the supported-MIME table so it needs the extracted-text path.
- 2026-10-28: Docs say transcribe is multipart POST {base}/asr/transcribe (request JSON + audio WAV) with DIARIZATION speaker labels and turn-level timestamps only.
- 2026-10-28: Live Meta check deferred by operator choice: check_meta validates (PDF xref ok, fail-fast ok) but made no live calls; run it before the intake step.
- 2026-10-29: reasoning_effort plumbed via META_EFFORT_AGENT (unset = server default) and META_EFFORT_FAST (default low); 'none' rejected client-side per docs.
- 2026-10-29: Effort delta, single-sample check_meta: Spark structured default 5.27s/962tok vs low 3.15s/378tok; Wonder tool loop 11.65s/261tok vs 16.00s/171tok (latency noisy); Wonder PDF out 1368 vs 1274. FAST stays low; AGENT stays server default for diagnosis quality.
- 2026-10-29: Additive schema only: new RunEvent table plus CaseFile document_id/problem_text/status/run_id/grounding_rate; no destructive change.
- 2026-10-29: New cases blueprint (dashboard, new, detail, events); case routes are student-only (professors 403, non-owners 404) until the professor case-file view lands.
- 2026-10-29: Intake pipeline runs in a daemon thread with its own app context; the case page polls JSON events every second and reloads on done/error.
- 2026-10-29: Uploads validated by extension plus magic bytes, stored UUID-named under uploads/ with a 10 MB cap; PDF via pypdf, DOCX via stdlib zip, scanned PDFs fall back to native file input.
- 2026-10-29: Evidence quotes verified as normalized substrings in code; ungrounded quotes dropped and the grounding rate stored on CaseFile.
- 2026-10-29: Diagnosis uses META_MODEL_AGENT with structured output; the document is delimited data with an ignore-instructions guard against prompt injection.
- 2026-10-29: samples/ holds two original synthetic excerpts with planted flaws plus expected.json as committed demo/test fixtures.
- 2026-10-29: Diagnosis calls get a 180s timeout (live e2e: Wonder took 78s on a 2-page excerpt; the 60s default timed out 3/3); routine calls keep 60s.
- 2026-10-29: Redesign tokens live once in templates/_head.html (Tailwind v4 @theme); original inline-SVG logo/icons plus favicon; Fraunces display + Inter UI.
- 2026-10-29: Case stepper stages derive from real RunEvents and toasts render server-side (no-JS safe); error pages share the macro set.
- 2026-10-29: Parallel diagnosis: 3 concurrent Spark specialists (FAST model) plus a Spark merge; live probe 13.4s wall (specialists 5.5/6.1/6.3s, merge 7.0s, ~7.4k tokens) vs 78s single Wonder call.
- 2026-10-29: Specialist or merge failure degrades (flagged partial result), it never kills the run unless all specialists fail; event seq guarded by a thread lock; SQLite WAL plus 5s busy timeout.
- 2026-10-29: Seed holds 20 professors from an importable PROFESSOR_SPECS table (deterministic fresh-db ids 1-20); seed refreshes stale sample profiles, still convergent.
- 2026-10-29: MatchResult stores one row per ranked match (rank, score, reasons, caveats, next_slot).
- 2026-10-29: Matching is a Wonder tool loop (6 iterations, 12 calls, 180s timeout, 5 attempts) plus a structured ranking validated in code (ids exist, 3 matches) with one retry.
- 2026-10-29: Tool budgets raise ToolBudgetExceeded; matching degrades to ranking-from-findings instead of failing (live: a 26-call sweep is now capped; converged run used 9 calls).
- 2026-10-29: Ranking prompt carries the tool findings transcript, not just the loop summary.
- 2026-10-29: Professors directory and profiles are public; case routes stay student-only.
- 2026-10-29: Evals are live scripts (never pytest): eval_diagnosis measures recall/grounding/latency parallel-vs-single; eval_matching scores top-1/top-3 over 30 generated cases; reports go to docs/eval/.
- 2026-10-29: ProfessorProfile gains nullable first_name/last_name/title/rank; seed assigns 20 fictional titled names and refreshes stale sample display names (convergent); numbering dropped so NN implies nothing about user ids.
- 2026-10-29: Ranking scores must be integers 0-100 strictly descending; order-only violations are sorted and persisted flagged (MatchResult.score_flagged), structural violations still raise after one retry.
- 2026-10-29: Ranking prompt carries numeric score anchors (90+ full high-severity coverage, 75-89 most gaps, 60-74 partial, sub-60 weak fit).
- 2026-10-29: Timeline tool events show a one-line human summary; raw args/results move to the event payload behind a Details toggle (server and live rows).
- 2026-10-29: Prices render as NGN via the ngn filter (thousands separators); seed rates are sample pricing, labeled in the UI.
- 2026-10-29: tzdata 2026.6 pinned so ZoneInfo('Africa/Lagos') resolves on Windows.
- 2026-10-29: Dashboard case cards show the diagnosis core_problem headline when a diagnosis exists.
- 2026-10-29: Booking reuses scheduled_at as the naive-UTC slot start; 60 minutes is a SLOT_MINUTES constant (end computed); unique(professor_id, scheduled_at) is the race backstop — recreate dev DBs, create_all cannot add it to existing tables.
- 2026-10-29: Booking gains case_id/meeting_url/consent_share_diagnosis; demo checkout sets status confirmed, a Jitsi URL with a random token, and a DEMO- payment ref.
- 2026-10-29: Slots come from the weekly availability grid for day offsets 1..14 in WAT; submitted keys are re-validated against a fresh grid and booked starts are filtered.
- 2026-10-29: Booking requires a MatchResult for the (case, professor) pair (404 otherwise); /sessions routes live in the student-workspace blueprint because the /bookings prefix does not fit them.
- 2026-10-29: The consent checkbox is mandatory; demo card fields are ignored server-side and never stored.
- 2026-10-29: Times are stored UTC, rendered WAT server-side, with a JS local-time hint from a data-utc attribute.
- 2026-10-29: Email sends over HTTPS via Resend or to a local .eml outbox (default); SMTP rejected because Render's free tier blocks its ports.
- 2026-10-29: DEMO_RECIPIENT_OVERRIDE reroutes every email to one inbox with a "Demo: intended for" banner; @example.com is refused by the Resend provider without it.
- 2026-10-29: EmailLog rows are idempotent per (booking, kind); one retry on transport/5xx, 4xx fails fast; mail failures are logged and never break the booking.
- 2026-10-29: The case-file email goes out only with the consent flag; the 45-minute agenda is a static template filled with the actual top gaps (no model call).
- 2026-10-29: Booking emails send synchronously in the checkout request (demo scale); move to a worker if Resend latency ever matters.
- 2026-10-29: /dashboard branches by role (students keep cases, professors get upcoming bookings); the case file lives at /dashboard/bookings/<id>, professor-only, consent-gated, 404 otherwise.
- 2026-10-29: Email and case-file page share case_file_context() so both surfaces always show identical content.
- 2026-10-30: Checkout bug: duplicate POSTs re-validated the slot against a grid the first request had already mutated (400 "Pick a valid slot" despite a created booking); retries on other slots duplicated bookings.
- 2026-10-30: Checkout carries a per-render idempotency token (unique Booking.idempotency_key), resolved before slot validation; retries 303 to the same confirmation; checkout ends in 303, never 302.
- 2026-10-30: Tests stub werkzeug scrypt with a behavior-preserving fast hash (login right/wrong/NULL/empty semantics intact); suite 277s to 36s, production hashing unchanged.
- 2026-10-30: Sessions are requested, not booked: requested|accepted|declined|reschedule_proposed|cancelled|expired|completed; checkout creates requested with a held demo payment and 48h expiry.
- 2026-10-30: Full unique(professor,start) replaced by a partial unique index over active statuses (sqlite_where/postgresql_where); terminal bookings vacate the slot. Recreate dev DBs.
- 2026-10-30: Request state machine is an explicit 8-edge TRANSITIONS table with conditional-UPDATE flips (lost races see rowcount 0); professor-only accept/decline/propose, student-only cancel/answer; completed has no inbound transition yet.
- 2026-10-30: Proposed slots must be future and unoccupied (checked, not grid-locked); proposal acceptance re-checks plus the index backstop.
- 2026-10-30: Meeting links are minted at request time but revealed only when accepted (display gating, no second link).
- 2026-10-30: Request expiry is a lazy sweep on booking reads plus a `flask expire-requests` CLI command; expiry releases slot and payment.
- 2026-10-30: Notifications: Notification rows, nav bell with unread count polled every 20s, /notifications inbox plus mark-all-read; exactly 5 events (request to professor; accepted/declined/proposal/expired to student), cancels and answers silent.
- 2026-10-30: Transition emails: session request (case file plus review link, no meeting link) and receipt at checkout; confirmed to both with the link on accept; declined with reason; same override/banner/idempotency rules.
- 2026-10-30: User-driven notifies live in the views; the expiry notice lives in expire_booking so lazy, CLI and guard paths all emit it.

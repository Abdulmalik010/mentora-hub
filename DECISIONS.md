# DECISIONS.md — one line per architectural decision.

- 2026-10-28: Meta calls go through the OpenAI Python SDK pointed at the Meta base URL (Meta publishes no dedicated client; this is the docs' recommended path).
- 2026-10-28: Chat Completions protocol first for lower scaffold complexity; switch to Responses API later if multi-turn reasoning continuity proves necessary.
- 2026-10-28: Model IDs come only from env vars (META_MODEL_AGENT/FAST/TRANSCRIBE) with no code defaults, so credit spend stays configurable.
- 2026-10-28: META_BASE_URL defaults to the documented https://api.meta.ai/v1 but is env-overridable; META_API_KEY has no default and fails fast.
- 2026-10-28: Tool loop depends on a ChatClient protocol (SDK adapter in prod, fakes in tests) so agent logic is unit-testable with no network.
- 2026-10-28: Retries use our own exponential backoff (rate limits, transport/timeout errors, 5xx) with the SDK's built-in retries disabled to avoid stacked retry storms.
- 2026-10-28: Tables are created with db.create_all and no migrations until the schema stabilizes after the auth step.
- 2026-10-28: Roles/statuses/levels are plain strings without DB CHECK constraints; validation moves into forms/services when those steps land.
- 2026-10-28: User carries email (unique), password_hash (nullable until auth), display_name, role, is_sample flag and timestamps.
- 2026-10-28: Foreign keys are wired now (profiles→user, documents/casefiles/bookings→users, sessions→bookings, notes→student/session).
- 2026-10-28: Datetimes are stored naive UTC (SQLite has no tz-aware type); revisit with timezone-aware columns if we leave SQLite.
- 2026-10-28: ProfessorProfile.rate is a unit-less float; currency is decided at the booking step, not guessed now.
- 2026-10-28: Seed data is synthetic, @example.com emails, is_sample=True, "[SAMPLE DATA]" bios; seed is idempotent get-or-create by email.
- 2026-10-28: Email (Resend vs SMTP) and PDF (reportlab vs WeasyPrint) providers stay undecided; services are typed NotImplementedError stubs.
- 2026-10-28: Verified on the machine's Python 3.14 while keeping the code 3.11-compatible; no 3.11 interpreter is installed here.
- 2026-10-28: Pinned exact versions (Flask 3.1.3, Flask-SQLAlchemy 3.1.1, SQLAlchemy 2.1.6, Werkzeug 3.1.9, openai 3.40.0, python-dotenv 1.2.4, pytest 9.2.0) for reproducible builds.
- 2026-10-28: API key reads META_API_KEY first, MODEL_API_KEY second (docs-verified name); fail fast when neither is set.
- 2026-10-28: Session auth with Werkzeug hashes and no CSRF yet; Flask-WTF is mandatory before any shared deploy.
- 2026-10-28: Passwords need 8+ chars at the app layer; NULL-hash rows (seed) can never log in.
- 2026-10-28: Logout is POST-only; login honors relative next targets only (open-redirect guard); failures are generic to block enumeration.
- 2026-10-28: Home page is a factory-level route so the blueprint structure stays exactly as specified.
- 2026-10-28: Seed accounts share one env-provided demo password; seed refuses to run without SEED_DEMO_PASSWORD and reports sample rows only.
- 2026-10-28: SECRET_KEY has no default and the factory fails fast without it outside TESTING; cookies are HttpOnly + SameSite=Lax with Secure via SESSION_COOKIE_SECURE.
- 2026-10-28: Flask-WTF CSRFProtect guards every POST form including logout; pinned Flask-WTF 1.3.0.
- 2026-10-28: httpx 0.28.1 pinned for the Meta transcribe multipart call.
- 2026-10-28: Docs say native PDF input is a chat file block (base64 data URL + filename); DOCX is absent from the supported-MIME table so it needs the extracted-text path.
- 2026-10-28: Docs say transcribe is multipart POST {base}/asr/transcribe (request JSON + audio WAV) with DIARIZATION speaker labels and turn-level timestamps only.
- 2026-10-28: Live Meta check deferred by operator choice: check_meta validates (PDF xref ok, fail-fast ok) but made no live calls; run it before the intake step.
- 2026-10-29: reasoning_effort plumbed via META_EFFORT_AGENT (unset = server default) and META_EFFORT_FAST (default low); 'none' rejected client-side per docs.
- 2026-10-29: Effort delta, single-sample check_meta: Spark structured default 5.27s/962tok vs low 3.15s/378tok; Wonder tool loop 11.65s/261tok vs 16.00s/171tok (latency noisy); Wonder PDF out 1368 vs 1274. FAST stays low; AGENT stays server default for diagnosis quality.
- 2026-10-29: Additive schema only: new RunEvent table plus CaseFile document_id/problem_text/status/run_id/grounding_rate; no destructive change.
- 2026-10-29: New cases blueprint (dashboard, new, detail, events); case routes are student-only (professors 403, non-owners 404) until the professor case-file view lands.
- 2026-10-29: Intake pipeline runs in a daemon thread with its own app context; the case page polls JSON events every second and reloads on done/error.
- 2026-10-29: Uploads validated by extension plus magic bytes, stored UUID-named under uploads/ with a 10 MB cap; PDF via pypdf, DOCX via stdlib zip, scanned PDFs fall back to native file input.
- 2026-10-29: Evidence quotes verified as normalized substrings in code; ungrounded quotes dropped and the grounding rate stored on CaseFile.
- 2026-10-29: Diagnosis uses META_MODEL_AGENT with structured output; the document is delimited data with an ignore-instructions guard against prompt injection.
- 2026-10-29: samples/ holds two original synthetic excerpts with planted flaws plus expected.json as committed demo/test fixtures.
- 2026-10-29: Diagnosis calls get a 180s timeout (live e2e: Wonder took 78s on a 2-page excerpt; the 60s default timed out 3/3); routine calls keep 60s.
- 2026-10-29: Redesign tokens live once in templates/_head.html (Tailwind v4 @theme); original inline-SVG logo/icons plus favicon; Fraunces display + Inter UI.
- 2026-10-29: Case stepper stages derive from real RunEvents and toasts render server-side (no-JS safe); error pages share the macro set.
- 2026-10-29: Parallel diagnosis: 3 concurrent Spark specialists (FAST model) plus a Spark merge; live probe 13.4s wall (specialists 5.5/6.1/6.3s, merge 7.0s, ~7.4k tokens) vs 78s single Wonder call.
- 2026-10-29: Specialist or merge failure degrades (flagged partial result), it never kills the run unless all specialists fail; event seq guarded by a thread lock; SQLite WAL plus 5s busy timeout.
